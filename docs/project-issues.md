### Q07的已核对证据与讨论方案

- `backend-go/assessment.go` 使用 `deckForTextModel` 后发送文字方案，明确将评审范围标为“方案辅助评审，不是成品画面验收”。提示复用动画的每幕、时长标准，并含固定浮力检查；没有按当前课题明确图表的教学目的、有效证据及结论。`completed` 表示评审报告返回，不表示课件通过质量验收。
- `backend-go/agents.go` 在成品保存、成功状态与结算后调用 `reviewCourseware`；`backend-go/review.go` 仅评审成功任务并保存辅助报告，不驱动问题页修复。因此，现有制作过程自动修复主要覆盖结构、请求及渲染错误，不能等同于独立模型已审核教学质量。
- `render-service-py/app.py` 的比较、练习及媒体区域包含固定填色面板，其面积与实际内容密度没有充分关联。文字方案合格仍可能渲染出空洞色块；需要检查真实画面。填色本身不是错误，应判断它是否服务于具体内容、分组、比较或重点。
- `backend-go/courseware_quality.go` 主要按媒体是否存在、数量及版式等判定；图表结构合法不证明数据、关系或结论有教学意义。数量约束可能让无价值图表也满足规则，不能用更多图表替代更好的图表。
- 现有视觉模型通道用于动画帧，没有接入课件截图评审；仅配置视觉模型不能自动补齐课件审核链路。已有真实评审抽测发现过浮力错误，但未覆盖无意义色块与空洞图表，也不是当前模型的质量验收。

建议流程仍待讨论：逐页教学规划 → 内容与图表生成 → 可计算数据核验和教学审核 → 渲染真实页面 → 截图视觉审核 → 仅修复问题页并复核。前三页完成此流程后交教师审核，通过后继续其余页面；交付前检查整套连贯性与重复表达，不重新生成合格页。

图表验收建议：能明确回答它帮助学生理解什么；数据或关系有依据；学生能据图作出与本页目标相关的观察、比较或推理；图文和答案一致。不适合图表的页面允许不用图表。视觉验收关注无意义填色、遮挡、可读性和信息层级，不设无依据的统一色块比例。审核问题需定位页及对象，数值问题由确定性校验处理，内容问题修内容，版式问题修布局；有界重试后仍失败应保存草稿和具体原因，不能冒充审核通过。

验证建议：收集用户实际坏页及合格对照页，覆盖空洞色块、任意数据图、图文矛盾、错误答案与确有教学用途的填色图示，分别统计漏检和误报；不以模型自己的总分作为验收结论。本轮未实施上述流程，也未调用付费模型。

### 面向非技术用户的恢复体验与防复发

用户补充：项目使用者很可能不懂代码，输出技术失败原因没有实际帮助；系统应承担处理责任，并降低同类问题再次出现的概率。此要求已记录，以下为讨论方案，尚未实施。

用户界面应说明正在处理的页、课件保存情况和可执行动作。自动恢复期间可显示“正在调整第5页的图表，其他页面已保存，无需操作”；短暂服务异常应在后台恢复，不增加手动确认。资料确实不足时只询问教学信息，例如教材版本或原始数据，不要求用户解释模型或渲染报错。持续无法完成时显示“课件暂未完成，已保存的页面会保留，可稍后继续”，不要承诺无法保证的恢复时间；收费提示必须与实际账务状态一致。技术诊断保留在后台供维护使用。

防复发需同时改变生成约束、交付关卡与验证方式：

1. 从源头取消为凑数量而添加图表的要求；要求图表有本页教学目的、有效数据/关系及可支持的结论。渲染布局按内容调整，不默认铺满空洞填色区域；必要的科学图示不能用装饰或纯文字替代后声称完成。
2. 每页审核实际渲染画面与内容，问题页不得进入已验收状态；审核不可用属于“未检查”，不能作为通过。只有当前修订通过规定检查后才进入教师审核或最终交付，修改后旧审核结果失效。
3. 同类问题重复出现时改变修复策略：空洞面板修改布局，无依据图表替换为有依据的例子或合适表达，数值矛盾重算并核对；不得仅反复改提示、改标签或隐藏检查。局部修复后同时检查邻页衔接，不重做合格页。
4. 用户已反馈的坏页加入长期回归样例，并加入合格的填色、比较与图表对照页；验收必须包含真实渲染、实际审核、修复后复核和未知问题页，不只测试接口与返回格式。每次更换模型、提示、版式或审核规则均重验相关质量样例；未满足验收标准不得宣称已解决。
5. 持续记录问题类型、漏检、误报、修复成功率及用户退回情况；反馈进入可复验样例和规则维护，不宣称系统自动训练或自动学会。分别衡量缺陷产生率和缺陷交付率，不能将“坏页未交付”称为“永不产生坏页”。

目标是减少同类坏页生成，并尽量在交付前发现和修复；生成模型及审核仍有不确定性，不能保证任何内容永远无误。故障恢复有界，未达到质量要求的草稿不得冒充完整成品。

### Q08：在线检索混入不可用或错误资料

2026-10-10用户反馈：在线检索经常找到不能用的资料或错误信息，状态为已出现待解决。本轮核对代码，未逐项验证历史结果，也未调用在线搜索或付费模型。

当前证据：`backend-go/agents.go` 把年级、科目、教材及课题拼为一条检索查询；`backend-go/knowledge.go` 在线搜索取最多五条结果，没有按知识点拆分查询或来源分层策略。优先使用搜索服务提取正文，缺少时自行抓取；抓取失败会退回搜索摘要，该摘要仍可作为Source进入生成。`relevantPassages` 主要做关键词匹配、广告噪声过滤及相邻公式/条件保留，逐条来源片段预算1800字；不能证明事实正确或教材匹配。可选重排只有相关性排序，没有事实验收门槛；去重按所选正文完全相同的哈希，不足以识别同一错误的多站转载。已有来源快照、时间和哈希有助于追溯，但不是正确性证明。`evaluation.go` 的五题验收只测知识库命中与排名，不测在线事实、资料可用性或引用支持程度。

讨论建议：先建立经过核对的数学/物理核心资料库，按年级、教材版本、章节、概念及适用条件整理；在线搜索补充实验、应用案例和缺失依据，不让每次通用搜索决定基本定义与公式。教师上传资料是教学输入，也需检查错误与冲突，不能默认权威。出版社、教育机构、课程标准和可靠科学机构等优先，但来源类别本身不保证每条信息正确。

检索改进分六项：

1. 按实际缺失信息拆分少量查询：定义与前提、典型误区、例题或实验等；保留年级/教材约束，合理预算，资料足够时不重复搜索。
2. 来源筛选与正文质量检查：排除下载列表、登录页、广告、空正文及关键公式/图像缺失的片段；搜索摘要用于定位候选，不单独支持关键教学结论。缺失前提时扩大上下文或另找来源，不强行截断。
3. 按内容整理证据：关键结论对应原文位置、适用条件、来源与版本；排序同时考虑教学适配与证据支持。相关不等于正确，有引用编号不等于引用能支持结论。
4. 处理冲突和转载：关键且存疑的说法查独立依据，识别同源转载；不按网页数量投票。公式、单位、例题答案尽可能程序核验，物理实验还需检查条件与安全。
5. 资料不足时自动换查询/来源；可信资料库足够时继续制作，不因补充搜索失败阻断。仍缺少核心依据时只询问用户能回答的教材或资料问题，不编造案例、实测数据或教材页码，也不伪装审核完成。
6. 将实际坏结果加入可复验样例，测可用正文率、错误资料过滤、正确资料误删、教材匹配及结论-引用支持；同时保留固定快照测试和真实在线抽测。缓存需保留来源与版本、失效和修订机制；不把缓存当作永久正确的白名单。

其他学科的扩展判断：减少公式与精确图形通常会降低渲染难度，但不必然降低整体教学难度。语文涉及原文与解释边界，英语涉及自然用法、语境和语音，历史涉及史料、时间和因果解释；需要各自的资料与审核标准，不能只换科目名称复用数学物理标准。
