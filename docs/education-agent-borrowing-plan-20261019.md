## 1. 目标与原则

让教师通过自然对话说明教学意图，系统据此规划、制作可编辑课件，教师核对后交付。课件优先，动画辅助；教学资料与设置辅助对话，不要求新手先完成一套复杂表单。

优先改善六项能力：

1. 维护一份当前需求，普通回复只解释本轮变化，减少重复翻阅。
2. 将学习目标与讲解、活动、练习建立可检查的对应。
3. 按教学任务选表达方式，避免每页套用同一结构。
4. 需要图片或动态演示时有可用素材、有退路、有来源。
5. 重点事实和跨页矛盾必须核验，无法完成时如实显示。
6. 只保存教师明确允许跨课使用的偏好。

复用现有 Vue、Go、PostgreSQL、模型接口与 Python PPTX 渲染链路，不另建智能体平台或记忆服务。所有资料、素材、任务、偏好及下载均校验当前企业和成员。真实模型与样例模式分开记录；机器核验不代替教师审核。

对话本身不创建付费制作任务。开始制作、预留额度、前三页确认、继续制作和最终交付，继续遵守现有授权与审核关卡。

## 5. 图片与动态表达：先验收已有链路，再补退路

### 5.1 图从哪里来，联网关闭时怎么办

[自动配图入口](../backend-go/courseware_images.go) 在 `UseWeb=false` 时返回 `disabled`，不会继续自动联网找图。当前实现不是离线配图系统；关闭联网后，单靠现有自动检索仍可能整课没有图片。

建议按以下顺序补齐可操作退路：

| 条件 | 使用方式 | 实施状态与边界 |
| --- | --- | --- |
| 已有可访问的私有图片素材 | 由教师选择或由系统提出候选，经确认复用 | 已有私有素材引用基础；跨资料自动发现与选择需要另验收 |
| 教师持有合适图片 | 沿用上传入口，填写说明和出处 | 已有上传基础，需验证在首页/编辑页容易找到 |
| 图片在已上传 PDF/PPT 等资料中 | 在权限范围内提取并保存出处，再给教师选用 | 自动提图属于建议新增，现行 SPEC 明确未将任意文档自动提图视为已实现；先做小范围切片并同步范围 |
| 无合适实景图片，但适合结构表达 | 优先现有程序绘图、示意图 | 不调用生图模型也可工作，标明“示意图” |
| 仍需要 AI 图片 | 作为后续可选能力，明确标注 AI 生成及用途 | 当前未接入 AI 生图；涉及外部服务和费用，另行确认后实施 |

2026-10-19稍后的d0f9a11、a5f8c30已实现待确认候选留存、暂停草稿确认/选图/上传/跳过及保存，不再重复开发，见[配图恢复记录](courseware-image-recovery-20261019.md)。

关闭联网时，界面应明确显示“自动联网配图已关闭”，给出上传或保留无图页面的操作。当前自动入口返回disabled，提示仍建议手动检索；手动coursewareImagesSearch未检查st.Input.UseWeb，前端也未接收开关。建议增加清楚的单次联网授权，或要求重新开启本课联网，并前后端一致实施，不能宣称已做到。私有素材只有按ID访问、上传及当前候选选择，没有通用素材列表/搜索入口；上传的MediaAsset.Provenance可为空，不能宣称所有上传已强制填写完整出处。不得用AI生成的历史照片冒充史料，也不得用装饰图凑覆盖率。

### 5.2 来源、相关性与事实分开核对

当前链路已有视觉相关性审核、来源记录、私有保存和权限状态处理。来源或许可不明的网页候选不能静默自动采用；本方案不改变现有确认边界。

候选相关性提示词已要求具体人物/事件/时期得到来源说明支持，但明确说明“不证明史实或授权合法性”；仍没有独立的历史图注事实认证或单独结果字段。替换图片后已有页面hash及依赖失效机制，不必另做同一套页面失效流程。

历史配图另核对人物、年代、地点、事件与页面结论是否一致，并保留实际支持依据。Commons 描述和视觉模型的判断都是待核对信息，不能作为事实认证。无法证实身份或时间时，降低图注具体程度或不用该图，不能补编图注。

教师替换或删除图片后，相关性、图注事实检查与页面审核应按受影响内容失效；保留未变化页面。出处、作者、许可名称和许可链接应能在素材详情及导出备注中追溯。

### 5.3 GIF、静态图与点击分步的选择

当前已有函数曲线和 PPT GIF 路径。仍需确定的是不同课堂任务的默认方式及放映兼容性，而不是从零建设 GIF 支持。

| 教学用途 | 本轮建议 | 必须验证 |
| --- | --- | --- |
| 观察二次函数参数变化、反比例函数曲线变化 | 复用现有 GIF；有精确操作需求时保留网页函数演示 | 变化范围、曲线计算、标签、播放节奏与 PowerPoint 放映 |
| 教师逐步讲解推导或揭示答案 | 先用现有静态页面、备注和明确分步安排 | 不提前泄露答案，教师能控制节奏 |
| PPT 原生“点击逐条出现” | 作为对照候选，是否实现由课堂试验决定 | 目前不能写成已支持；需验证原生动画、编辑能力与导出链路 |

同一函数课题生成静态、GIF及网页演示对照；如果制作原生点击候选，再加入对照。由数学教师评价“能否讲清变化、能否停在关键状态、是否增加操作负担”。GIF 内部是图片帧，不承诺在 PowerPoint 内逐点编辑；静态原生图表和课件结构参数的编辑能力分别验收。静态截图只能检查首帧，必须另做桌面 PowerPoint 放映检查。

### 5.4 配图验收指标

- **有效配图覆盖率**：最终带有合格图片的页面数 / 教师事先认定确实需要图片的页面数。联网开启、关闭分别统计，同时记录联网开关、无图原因和所用退路。
- **误收率与误拒率**：对实际评过的候选，由学科教师独立标注相关/不相关；误收为不相关候选中被通过的比例，误拒为相关候选中被拒绝的比例。报告各自分母与样本数。
- **作者与许可完整率**：实际采用外部图片中，出处、作者或公共领域归属、许可名称及链接均可追溯的比例。自动采用要求完整，不以高平均值掩盖单张缺失；教师上传单列来源声明，不伪造许可。
- **替换/删除率**：教师审阅后替换或删除的自动配图数 / 自动配图总数，并记录不相关、错误事实、授权疑问、画质或课堂用途等原因。
- **动态可用性**：检查真实 PPTX 放映、GIF 播放、首帧可读性、静态退路和函数关键状态；不以导出成功替代教学评价。

在现有规划结构上新增目标列表与每页引用，不单独增加一次“目标映射模型调用”。让规划模型随现有输出填写字段，Go 做确定性检查。

```json
{
  "learning_goals": [
    {"id": "g1", "text": "根据史料解释变法失败的原因", "core": true}
  ],
  "pages": [
    {"position": 1, "goal_refs": ["g1"], "checks_goals": [], "depends_on": []},
    {"position": 2, "goal_refs": ["g1"], "checks_goals": ["g1"], "depends_on": [1]}
  ]
}
```

以上仅展示新增映射字段，真实规划继续保留原有 `goal`、`task`、`visual` 等字段。`goal_refs` 说明服务哪个目标，`checks_goals` 说明该页实际检验哪个目标，避免把“提到目标”误算成“检验目标”。目标 ID 在本课内稳定，不用目标文本精确匹配。

### 6.2 程序检查范围

1. 目标 ID 唯一，引用存在，`checks_goals` 是本页 `goal_refs` 的子集。
2. 每个核心目标至少有一页覆盖，并至少有一项实际检验任务。
3. `depends_on` 有效、无环；依赖讲解先于对应练习。诊断题或拓展例外需显式标明，不能静默放行。
4. 复制、删除、重排页面后更新位置依赖并重查；目标引用不因页号变化失效。
5. 历史规划缺少字段时标“未建立目标映射”，保持查看和编辑兼容，不补造已通过结果，也不默认重做旧课。

程序只能证明结构完整，不能证明练习真的能测出该目标。任务与目标的语义关系并入现有重点内容审核及教师评分，不另起一轮模型检查。发现字段错误先返回具体问题，仍沿用现有有界修复，不无限重试。

## 7. 按教学目的选版式，减轻模板感

模板感不只是提示词问题，也来自素材不足、模型固定选择同类对象、渲染比例单一和修复只关心溢出。新增配图与函数能力提供了表达基础，还需要让规划真正使用它们。

源码复核：planCourseware已要求每页视觉方案、观察/比较/推理用途及互补组合，逐页提示也按教学任务组织表达，内容审核检查无意义图表及目标关系。本节应先评估实际页面和渲染约束，局部修正失败样本，不将“新增按用途提示词”作为从零建设的主任务。

| 教学任务 | 应采用的表达 | 避免的机械套用 |
| --- | --- | --- |
| 历史因果分析 | 有依据的史料、人物/事件图片、因果链与条件对照 | 所有学科都铺时间线或装饰性年代标签 |
| 语文文本细读 | 原文、批注、词句比较、解释依据 | 把文本分析压成统一三列表格 |
| 数学推导与函数 | 条件、关键步骤、原生坐标图、适量参数演示 | 用无关照片替代推理，或一开始就展示练习答案图 |
| 物理过程 | 实验条件、现象、模型、受力/过程图 | 所有内容都做成固定卡片 |
| 数值比较 | 有真实或明确标示意的数据、单位与读图任务 | 为了有图表而伪造数据 |

实现依次落在既有 `Visual` 规划、`Slide` 对象选择和 Python 渲染器的局部调整。每页写明学生要观察、比较或推出什么；有合适对象才用，不强制每页配图。字体、配色保持一致，图文比例和节奏随任务变化。参考课件学习图文关系，不继承原课题事实。

验收检查真实 PPTX 的中文、公式、表格、图片和图注可读性；原生对象与图片分别说明可编辑边界。局部修改不得重做其他已审核页面。版式数量、色彩变化和图片数量不直接算教学质量提升。

## 8. 重点事实与全课一致性检查，提前落实

### 8.1 核验现状与不能忽略的缺口

当前服务启用 `key` 内容审核，代码能依据例题、答案、公式及“史实、年、原文、引用”等线索识别重点页。但关键词命中并不等于覆盖可靠；历史草稿、关闭审核配置、缺少来源或审核失败仍会留下未核验内容。

已有历史时间顺序检查只能识别有限形式的时序问题，无法证明具体年代和事件相符；化学检查也只覆盖可解析的简单分子方程式。不能据此宣布“全科内容已核验”。

源码复核：pageForReview仅提供当前slides及对应计划，保留conventions，去掉其他页notes。新规划课件assessTeaching仅汇总PageChecks；旧无规划辅助评审仍存在，但reviewCourseware只读取succeeded任务，明确不影响成品及结算。当前没有交付前跨页事实核验。

缺证疑虑也不是现有硬门禁：parsePageReview将uncertain降为suggestion，blockingPageIssues只拦error；配置关闭内容审核时，disabled加有效截图检查可通过。下方“缺证必检保留草稿”与交付前跨页检查是规则及实现建议，不能当作已生效，实施时须同步SPEC和HTTP状态/额度验收。

### 8.2 必检范围

- 历史：史料推论、人物/事件/地点/年代、重要因果结论，及历史图片的事实图注。
- 语文：原文和引文、作者归属、字词解释、译文、重要解读结论及其文本依据。
- 数学、物理、化学等：例题、答案、推导、公式适用条件、实验条件和安全结论。
- 全课：同一事件、案例、术语、数值、约定和答案前后一致。

来源必须是实际取得的原文、材料或可追溯证据。标题、目录、检索摘要、多个近似转载以及模型记忆都不能冒充原文核验。联网关闭时优先核对已上传资料；资料不足就标明缺证，不隐式联网。

### 8.3 如何接入

1. 规划阶段标识重点核验对象及来源需求；结构目标映射由程序完成。
2. 逐页阶段复用现有内容审核，将重点结论与真实出处并入当前调用。内容审核整体关闭时，必检内容保留“未核验”，不转由截图审核替代。
3. 全课阶段新增一次有界的跨页检查，必要时分片，在统一预算内核对已有结论与来源。**它是交付前必做检查，不能仅写成视成本决定是否接入。** 只有三页时也对已生成范围记录覆盖；整课完成后核对全课范围。
4. 跨页一致不代表事实正确。事实核对和一致性结果分别记录，缺证页仍为未核验。
5. 已确认错误优先局部修复，记录受影响页面并重新核验；一般教学建议不阻塞交付。

对每页区分内容核验、配图相关性/图注核验、画面检查和教师审核；每项记录内容版本、范围及依据。跳过、失败、缺证均不得显示“已核验”。整课检查未覆盖到的页不能继承整课绿色标记。

**建议门禁**：必检项未完成时保留草稿及原因，允许查看、修改和补资料；不能自动进入“核验完成”的交付。沿用既有失败恢复、预留释放与不结算语义，不新增虚假的成功状态。若以后允许教师明确接受未核验风险后导出，须单独确定产品规则、展示和确认记录，本方案不默认开放。确定事实错误继续阻塞，不用教师点选把错误洗成通过。

## 9. 成员偏好独立存储，最后实施

当前 `previousTeachingFeedback` 用学科、年级、课题精确匹配读取最近 8 条带原因反馈。换课题名可能完全取不到；这些原因进入提示词时，也没有逐条取得跨课复用授权。不能把它包装成已经具备跨课偏好，更不能直接扩大查询范围。

建议新增一张 PostgreSQL 成员偏好表，和现有任务/页面反馈分开：

- 至少包含企业、成员、偏好类型、偏好值、适用范围、明确确认记录及时间。
- 优先有限类型：答案位置、文字密度、练习节奏、色彩习惯；每条文本建议最多 300 字，注入最多 10 条、合计 2000 字，前后端同时限制。具体限值在实施时固定并写测试。
- 教师主动选择“仅本课”或“保存为我的偏好”；已有反馈不自动迁移，不把课题事实、学生基础或学习目标转为长期习惯。
- 查询、保存、覆盖、删除均校验当前企业和成员；删除后不再注入，新一轮生成采用最新值。
- 当前明确要求高于偏好；偏好不能覆盖事实、来源、权限、审核门禁或费用授权。
- 偏好文本以带字段的非可信数据进入提示词，限制长度并明确不得作为指令执行；仅做 JSON 包装不等于消除提示词注入风险，最终权限仍由服务端控制。

原有反馈继续用于当前课题的修订；实施时同步明确反馈数据边界、长度及注入方式，避免旧课原因污染新课。验收覆盖主动保存、仅本课、覆盖、删除、成员隔离和恶意偏好文本，不增加独立记忆服务。

## 10. 调用、耗时与成本预算

### 10.1 当前真实约束

| 项目 | 源码行为 | 对本方案的约束 |
| --- | --- | --- |
| 模型调用上限 | 每生成/预留周期 `20 + 8 × P`，P 限制为 3–100 | 自动恢复、重启和删除调用明细不清零；不得另设旁路调用 |
| 配图审核计数 | `reviewCoursewareImage` 已调用统一预留函数 | 审核候选失败也占用调用；新增预算只做分配和可见性，不重复扣计数 |
| 单次候选审核 | 视觉请求最多45秒；网页与备用Commons各最多3次，理论合计最多6次视觉调用 | 两条路径独立计数；返回1或2个候选不限制评过数量，受90秒及总预算约束 |
| 自动图片检索 | 外层总计最多 90 秒，网页优先 65 秒、Commons 备用 25 秒 | HTTP 检索不等于模型调用，但仍耗时；视觉审核另计模型用量 |
| 前三页阶段 | worker 时限 15 分钟 | 新检查也在阶段期限内，不能在期限外偷偷补跑 |
| 剩余页阶段 | `min(3小时, 6分钟 + max(0,min(100,P)-3) × 120秒)` | 15 页约 30 分钟，22 页约 44 分钟；不是固定 40 分钟 |
| 并发 | 服务报告生成池 2、视频池 1 | 排队时间与实际执行时间分别记录，不能继续按单 worker 估算 |

依据：[预算](../backend-go/courseware_budget.go)、[图片调用与候选限制](../backend-go/courseware_images.go)、[检索分时](../backend-go/courseware_web_images.go)、[阶段期限](../backend-go/tasks.go)、[续作公式](../backend-go/courseware_batches.go)、[worker 实现](../backend-go/workers.go)。40 分钟仍出现在部分旧文档和小页数测试边界中，不能据此当作所有课件的运行时上限。

### 10.2 建议预算分配，不改变总上限

以下是新增功能的预算设计，尚未实施子预算调度。预算可在同一总额内有界调剂，但必须先给剩余页面生成及必检留出额度。

| 预算部分 | 建议额度 | 用途 |
| --- | --- | --- |
| 固定 20 次中的规划 | 最多 6 次 | 需求到规划、结构修正，含目标字段；不为映射另发请求 |
| 固定 20 次中的全课核对 | 预留 2 次 | 当前阶段/全课事实与跨页核对，至多两次有界调用或分片 |
| 固定 20 次中的恢复余量 | 12 次 | 必要失败恢复、额外独立解题/专项核对等，不默认全部消耗 |
| 每页 8 次中的生成/局修 | 目标不超过 4 × P | 生成、结构修正、局部内容修复；继续遵守已有重试上限 |
| 每页 8 次中的逐页检查 | 先留 2 × P | 内容和画面；复杂独立解题等超出部分从恢复余量调剂 |
| 每页 8 次中的图片相关性 | 建议总计最多2×P，按实际需要；此子预算尚未实现 | 自动检索先每页1个，第二个仅在余量充足时评；网页及Commons须共享计数，不能把各3次误作合计3次 |
| 结构目标映射 | 0 次新增模型调用 | Go 校验引用、覆盖、依赖；语义检查并入已有审核 |

例如 15 页总上限为 140 次，上表分配为 20 + 60 + 30 + 30。它是保护上限，不是正常课件应消耗的目标；没有图片需求的额度不必使用。图片候选不应挤掉答案、史实、引文等必检。教师主动重新搜索仍计入统一调用上限，不能通过编辑入口绕开预算。

全课核对若两次调用仍无法覆盖实际内容，记录具体未覆盖范围并保留未核验，不压缩到丢失关键依据后假装全课通过。大页数是否调整分片数或分配，以真实耗时和误漏检数据另行决定，不自动放宽总上限。

### 10.3 时间及耗尽后的行为

所有新增检索、图片审核和一致性检查都使用现有阶段的父 context，计入该阶段时限；当前代码不存在独立的“整课统一 40 分钟计时器”。教师等待审核时间、排队时间另列，不混进模型运行时长。

建议全课核对总时段先限制在 90 秒内，两次调用各最多 45 秒，并以父期限剩余时间为上限。自动配图沿用每页检索最多 90 秒，但需要依据整课剩余时间提前停止；不能把“每页都有 90 秒”当成整课必然容得下。调度前估算剩余必检时间，优先停可选图片。

- **可选配图耗尽**：停止自动候选调用，保留无图页与“未配图/未完成相关性审核”原因，提供上传、替换或静态示意退路；未审图片不插入正式课件。
- **必检缺证、调用/时间不足或模型不可用**：标出对象和原因，保留草稿；不自动标通过、交付或结算。是否能继续由现有恢复规则决定，不自动新开收费周期。
- **整个生成预算耗尽**：沿用保存检查点、停止重复调用、不结算未完成任务的行为；不在后台无限补审。
- **取消或权限失效**：停止后续外部调用，保留既有权限与任务语义。

供应商成本以实际模型、输入/输出 token、调用成功/失败和延迟记录计算；网页检索请求及可能的第三方费用单列。业务积分与供应商费用分开报告，不用“免费修改”暗示模型成本为零。没有实际单价和真实运行记录前，不承诺具体节省金额或提速比例。

## 12. 基线、评价方法与验收记录

### 12.1 先固定 3 个学科、各 2 个课题

在新增方案实现前保存一组基线，建议如下；教材版本、实际年级、素材文件及学习目标由参与教师确认后冻结：

| 学科 | 课题 | 重点评价 |
| --- | --- | --- |
| 数学 | 二次函数的图像与性质 | 目标与练习、曲线特征、参数动态、答案可见性 |
| 数学 | 反比例函数的图像与性质 | 定义域、跨零限制、象限、静态/动态表达 |
| 历史 | 戊戌变法 | 史料结论、人物与年代、历史配图及因果任务 |
| 历史 | 辛亥革命 | 时序、人物/地点、图注事实、跨页一致性 |
| 语文 | 《背影》文本细读 | 原文、作者归属、引文、解释依据与理解检查 |
| 语文 | 《岳阳楼记》文本研读 | 原句、译文、语境和推论依据 |

这 6 个课题用于第一轮发现问题，不足以证明全科质量普遍提升。每个课题固定同一输入、资料文件指纹、模型版本、审核策略、页数/详略和网络条件。网络开启与关闭应配对运行，不能把网络差异当作改版效果。

已上线的对话折叠不能补写成“改动前基线已采集”。若需评价该改动，另用隔离环境运行固定旧提交作回溯对照；无法复现就明确写“缺少改动前基线”。本轮文档修订不切换当前工作区或服务。

### 12.2 谁评价，怎样评分

每个学科至少由一名对应学科教师评价教学效果，技术检查人员负责实际文件、状态、隔离和用量记录。条件允许时第二名教师复核事实争议；存在分歧时保留原始评分和依据。教师尚未参与的条目只记技术通过，不写“教师验收通过”。

A/B 课件隐去生成版本，顺序随机；相同量表分别评分。模型不得作为唯一评价者给自己的产物背书。

| 维度 | 记录方式 | 判定原则 |
| --- | --- | --- |
| 目标与任务对应 | 1–5 分，记录未覆盖/未检验目标数 | 程序映射通过不直接得满分，教师评任务是否真能检验 |
| 图文相关与用途 | 1–5 分，另记配图覆盖、误收/误拒 | 图多不加分，无必要的图可以删除 |
| 事实与引用 | 按严重度记录确定错误、无依据结论、引文不符的数量 | 严重错误不能被其他维度高分抵消 |
| 可读与可讲 | 1–5 分，记录遮挡、密度、动态图控制问题 | 1 为无法正常授课，3 为修改后可用，5 为可直接使用 |
| 教师修改与接受 | 修改时间、替换/删除原因、接受等级 | 区分直接接受、小修可用、大改、放弃，并记录评价人数 |
| 性能与成本 | 首字、三页预览、续作/整课时间、排队时间、调用与 token | 相同运行条件下比较，不把上限当作实际耗时 |

1–5 分采用统一锚点：1 为严重不满足，2 为需大量修改，3 为修改后可用，4 为少量修改，5 为满足本课要求。事实项继续独立计错，不用平均分掩盖。

为审核建立带依据的正确/错误对照：历史图注错人物/年代、语文错引文、答案冲突、正确重复、缺证但未证明错误等。记录误报、漏报及样本数；教师替换率与接受率都写清分母。候选被拒后也保留最小审计记录，才能评价误拒。

每个课题先做同条件一组 A/B；需要评估波动或速度结论时再做多次真实运行并报告样本数、中位数与范围。记录每次成功、失败、重试及人工校正，不能只选最好的一次。是否追加运行由实际预算决定，不能虚构结果。

### 12.3 测试边界与交付证据

- 新行为先写失败用例，再实现切片；HTTP 覆盖认证、企业/成员隔离、额度、任务状态与幂等。
- 渲染覆盖真实 PPTX；动态能力检查 GIF 和相应真实 MP4/HTML 输出，必要时做桌面放映。
- 浏览器覆盖多轮、历史展开、手改、摘要、中断、刷新、素材替换及明确制作。
- 模型 fixture 证明协议和流程；真实模型、人工课堂评价另存，互不冒充。
- 每条验收记录附提交、模型、资料指纹、配置、输出文件标识、调用/耗时及评分依据。缺少的记录标“未完成”，不提前承诺提升比例。

## 13. 暂不建设的内容

- 为借鉴项目重建前后端、增加另一套智能体调度或独立记忆服务。
- 强制教师填完整教学设计表，或新增多层默认确认。
- 无限自我审核、为每一项检查单独开模型调用。
- 自动迁移旧课事实、把点踩原因当成跨课偏好、跨成员共享私有资料。
- 为配图引入全站爬虫、无授权图库，或绕过联网开关。
- 将“网页采集”扩张为任意站点批量抓取；仍遵守 [GLOSSARY](../GLOSSARY.md) 与 [SPEC](../SPEC.md) 中单个公开页面、来源核对及确认入库的边界。
- 把 AI 示意图当史料，把样例输出当真实 AI 质量，或将截图审核当内容事实认证。

先补齐已实现能力的验收与退路，再用固定课题的数据决定下一步；不因功能列表变长就扩大平台范围。
