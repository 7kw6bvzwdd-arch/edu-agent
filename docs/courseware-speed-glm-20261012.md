# GLM课件生成与第一轮提速（2026-10-12）

用户要求切回GLM，并按之前建议优化。已将本机课件生成独立配置切回Ark的`glm-5-3-flash-260828`，保持独立文字审核和视觉审核。该模型课件调用继续禁用额外思考输出。旧的GPT配置仅保留在私有回滚文件，不输出密钥。

## 已应用的优化

1. 一次工作阶段或HTTP请求内缓存实际PPTX与Office截图。最多100项、64MB，结束即释放，不跨作品、成员或企业共用。PPTX键包含实际渲染的内容、备注、答案、配色、可编辑公式开关与页脚状态；页数/页序包含在页面列表中。截图按实际PPTX字节和抽样范围匹配，不能用单页截图替代页码不同的全套页面。
2. 文字审核期间同步准备当前页真实Office截图；内容有问题时仍不发起付费画面审核，等待截图工作安全结束并清理临时文件。
3. 当前页内容审核通过后最多提前生成下一页，与当前页的画面审核重叠。提前页不写入草稿、不跳过自己的结构/排版/文字/画面检查、不跨越三页教师预览关卡。复用前对完整请求依据做哈希比对。
4. 当前页修复立即取消旧的提前请求，基于修复后相邻页重新生成。任务取消、制作权限或执行轮次变化时停止提前请求，检查点和结算保持原规则。取消时供应商已消耗的调用仍可能产生供应商费用，业务积分不因提前生成增加。
5. 教材页原文已存在于来源快照时，不在教材说明中再重复整段正文；来源ID、原文、页码、版本和引用核验保留。参考风格也只发送一份，不削减必要证据。
6. 保存各阶段耗时、调用次数与缓存命中到制作事件；制作阶段时间不含教师等待，重叠环节不能直接相加。

## 实际抽测暴露的额外问题

真实GLM一次函数课题多次在图像页被反复修复，原因包括过长图示标题、多个媒体混排和审核误读小坐标刻度。这说明只切快模型并不能解决所有等待。

本轮明确图示标题保持简短，图示溢出修复提示聚焦图内标题/标签，保留原始数值与必要条件。实际函数图标题溢出时，排版器将图内标题改为“函数图像”，完整原标题（包括坐标）保留在备注；两条曲线与公式、底部提问同时显示导致图例挤占绘图区时，优先将底部提问完整移入备注释放空间。曲线、标记点、范围和公式均不改变。两项真实PPTX回归先复现溢出，修正后通过且核对所有数值与原文保留。审核同时获得程序实际绘图能力和标记点计算；数学坐标无量纲、共用原点0、只标部分等距刻度与可见窗口裁切均可有效，不因缺少每个整数网格判错。视觉审核仍检查实际截图、具体可见错误和图文数值矛盾。

函数图视觉审核额外提供同一真实截图的放大裁剪，保留整页，未修改图像内容、未替换生成素材、未额外启动Office。未因提速删除质量审核。

## 耗时口径与限制

历史调用中GLM单页生成中位约8.48秒，GPT约47.82秒，画面审核约17.16秒，文字审核约1.99秒；不同课题/版本的样本不构成质量或端到端速度对照。缓存和流水线收益取决于重复产物、审核与生成耗时、修复次数和供应商状态，不能承诺固定分钟完成。

本轮数学真实抽测中已经出现失败并保留真实原因，不把失败输出当成完整课件。真实全课教学质量、多课题成功率和匹配课题的端到端提速比例仍需继续验收；正式流程继续保存检查点并自动局部修复。
