## 1. 目标与非目标

**目标**：教师从课件页或首页对话描述一个知识点，系统产出一段**画面与语音对齐、带字幕、可离线播放**的教学动画；修改通过对话完成且只重做受影响部分。

**非目标**（明确不做）：

- 不做通用视频生成产品，不替代云视频情境素材工具
- 不做自由脚本执行（模型输出仍受 schema 约束）
- 不做多角色配音、背景音乐、音色克隆（后置）
- 不做通用物理引擎或符号计算系统
- 不在首版做跨浏览器像素级一致性承诺

## 3. 数据模型

一个版本包内包含两部分，物理上同包，语义上严格分离。

### 3.1 作者数据（模型可写）

| 字段 | 说明 |
|---|---|
| `scene[]` | 幕；含 `sceneId`（稳定 ID）、`intent`（教学意图）、`title` |
| `object[]` | 教学对象；含 `objectId`、类型（函数/几何体/受力体/电路…）、语义参数 |
| `narration[]` | 旁白；含 `sentenceId`（稳定 ID）、展示文本、朗读文本（可与展示文本不同）。**字幕不是作者字段**，由程序按句取展示文本生成 |
| `slot` | 组件所在版式槽位（主区/侧栏/左右/上下分区等，由原型声明可选值）；**不含像素坐标**，坐标由渲染器计算 |
| `action[]` | 动作；见 §4.3，显式绑定 `sentenceId` 与 `objectId` |
| `hold[]` | 教学停顿；见 §4.2 |
| `archetypeRef` | 原型引用，含版本（`flow.lanes@2`） |

### 3.2 构建结果（仅程序可写）

| 字段 | 说明 |
|---|---|
| `audio[]` | 实际音频片段、时长、哈希 |
| `timestamp[]` | 句子起止时间（句级，见 §5.1） |
| `timeline` | 计算后的全局时间轴（音频 ⊕ 停顿） |
| `assetHash` | 素材哈希 |
| `renderVersion` | 渲染器 + 原型 + 主题 + 字体版本 |

**禁止**：模型填写实际音频时长、伪造时间戳、手写 `timeline`。校验器发现作者数据中出现构建结果字段即拒绝。

### 3.3 版本、补丁与依赖重算

- 用户口中的"第 3 幕"是**表达**，入系统前先解析为当前版本的 `sceneId`。
- 每个补丁绑定 `baseRevision`。结果返回时若 base 已过期（迟到结果），**拒绝直接写入，保留教师原输入与修改意图**，不静默覆盖新版本。服务端基于最新版本重新生成并校验补丁；无法确定目标时才请教师澄清，不要求教师理解或手动执行 rebase。
- 构建结果**内容寻址**：输入哈希不变即复用，天然实现"只重算受影响的"。
- 补丁后计算**脏集合**，按下表重算，无关内容原样保留：

| 修改 | 重做范围 |
|---|---|
| 颜色、位置 | 对应画面 |
| 一句旁白 | 对应合成单元的音频、字幕及受影响时间轴；句级合成重做该句，段级合成重做所在段（§5.2） |
| 幕顺序 | 全局时间偏移与转场 |
| 学科参数或数学关系 | 相关图示、计算、旁白及校验 |
| 主题 token | **全部幕重渲染，但不重配音** |
| 原型版本 | 该原型的所有幕重渲染 |

### 3.4 版本绑定与确认失效

**一切确认都绑定内容，不绑定"作品"，也不绑定全局版本号。** 代表幕确认绑定的是**该幕的局部构建内容 hash**，覆盖范围明确为：该幕作者数据（对象、旁白、动作、停顿）+ 实际音频 + 素材 + 渲染依赖（原型版本、主题 token、字体、坐标系比例）。`revision` 只记录"确认来自哪一版"，**不作为失效判据**。

代表幕确认后不重做，**但不等于永久豁免**：

| 后续修改 | 对代表幕的影响 |
|---|---|
| 与代表幕无关的幕（其他幕的旁白、内容、顺序） | 保持已确认状态，不重做 |
| 全局参数、主题 token、字体、坐标系比例 | 影响其画面 → **撤销确认，重做并重新确认** |
| 代表幕自身的对象、旁白、原型版本 | **撤销确认，重做并重新确认** |
| 被代表幕复用的共享对象或跨幕参数 | 视为影响代表幕 → **撤销确认** |

判定依据即 §3.3 的依赖图：改动落在代表幕的脏集合内即失效。**全局 `revision` 与全局时间偏移本身不在该 hash 内**——生成其余各幕会改变全局版本与时间偏移，但代表幕的局部构建内容未变，其确认**保持有效**；只有真正进入代表幕脏集合的改动才撤销确认。撤销时须向教师明示「代表幕已因本次修改失效，需重新确认」，**不得静默沿用旧确认**。

成品验收同此规则，并额外明确：**历史成品的验收记录保留**（用于查看、下载与账务追溯），但**不能用于确认新修订**——新修订需要新的验收。

## 4. 时间轴

### 4.1 双驱动

时间轴 = **实际音频时长** ⊕ **教学必要停顿**。音频决定"讲多久"，停顿决定"要留多久"，二者共同生成最终时间轴，任一不可覆盖另一。

例：「观察物体完全浸没后的变化」说完之后仍需留出观察时间；该停顿不得被音频时长压缩。

播放器维护统一的**全局教学时间**，构建结果记录每个音频片段与全局时间区间的映射，不把某个音频片段的 `currentTime` 直接当作整段动画时间：

- 语音播放区间：全局时间对齐当前片段的实际音频位置，画面与字幕跟随该位置。
- 固定阅读、观察、提问留白与转场：由播放器单调计时继续推进全局时间，期间无旁白也能正常前进，画面按该时段设计保持或运动。
- 教师点击等待：冻结全局时间与音频，点击继续后进入后续区间。用户主动暂停同样冻结播放，不把等待的现实时间计入教学时间。
- 跳转与回放：先定位全局区间，再恢复画面、字幕和对应音频局部位置；目标处于无声区间时不误播前一段旁白。跳转前的计时与音频不得继续推进旧状态。

### 4.2 停顿类型

| 类型 | 语义 | 是否硬门 |
|---|---|---|
| `read` | 阅读画面文字 | 否 |
| `observe` | 观察现象/图形变化 | 否 |
| `ask` | 提问后留白 | 否 |
| `await` | 等待教师点击继续 | **是（无限等待）** |
| `transition` | 转场 | 否 |

同一份作者数据支撑两种播放模式：

- **自动播放**：`await` 降级为固定停留时长
- **教师分步**：所有 `await` 生效，无限等待点击

### 4.3 动作绑定句子

**不采用"第 i 句对应第 i 个元素"的隐式约定。** 一句话可控制多个对象，一个对象也可跨多句持续变化。每个动作显式声明：

```
{ actionId, sentenceId, objectId, anchor: begin|end, offsetMs, durationMs }
```

无对应旁白的元素绑定四种触发之一：

`atSentence(sentenceId, anchor, offsetMs)` · `afterAction(actionId)` · `atSceneStart` · `atSceneEnd`

### 4.4 状态是时间的纯函数

第一版选择以全局教学时间为输入的 `render(t)`：同一已构建版本在相同播放模式和时间位置，应恢复相同的教学画面状态，不依赖此前是否完整播放。这是首版实现选择，不宣称它是唯一实现方式。

**禁止脱离统一时间轴、自行播放且不能定位或恢复状态的教学动画**，不笼统禁止 CSS `@keyframes`。CSS 动画可通过 Web Animations API 获取并控制 `Animation.currentTime`；如采用该方式，同样须由统一时间轴控制暂停、定位和重放，不能与播放器各自计时。依据：[MDN Animation.currentTime](https://developer.mozilla.org/en-US/docs/Web/API/Animation/currentTime)。

门禁须实际验证语音区间、固定停顿、点击等待及跨幕跳转的状态恢复，不能仅凭采用纯函数就认定功能通过。

## 5. 语音与字幕

### 5.1 句级链路（首版）

```
sentenceId → 展示文本 → 朗读文本 → 音频片段 → 起止时间
```

首版**只做句级**。理由：句级已足够支撑"分幕时长对齐 + 整句字幕"；字级对齐算法成本高、收益集中在逐字高亮，后置。

**保留原文与朗读文本的关联是必要的**：阿里云文档明确提示字幕单元按发音生成，`12` 可能对应「十」「二」两个字幕单元，**字幕索引不能直接当字符串偏移**。因此即使只做句级，也必须分别保存展示文本与朗读文本。

### 5.2 合成分档

| 档 | 条件 | 做法 |
|---|---|---|
| A | 接口返回句级时间戳 | **按"段"合成**（连续数句一块），再切句边界；韵律完整、请求数少 |
| B | 接口不返回时间戳 | 逐句合成，用解码后实际片段时长拼接句级时间轴 |

**合成、缓存和修改失效的单位必须一致**：A 档按段缓存，改一句通常需要重合成所在段，并更新该段句子时间戳及后续时间偏移；不得承诺只重合成该句。B 档按句缓存，仅重合成变化句并更新受影响时间轴。两档都保留稳定 `sentenceId`，段级合成另外记录段与句子的归属关系。

首版根据真实账号探针和试听结果选定**一种**策略并写死为配置，验证自然度、字幕对齐和局部修改。**选定之后不存在运行时切换档位的降级链路**：该策略运行中失败时只走有界重试，重试耗尽即明确失败并如实告知教师，不得在运行时悄悄改用另一档合成。

理由：两档的缓存键与修改失效单位不同（§5.4、§3.3），运行时混用会让"改一句旁白要重做多少东西"不可预测，也会让计费与失败归因失真。切换策略属于重新验证后改配置，不是失败兜底。

B 档需额外验证**句间衔接**：响度一致性、拼接处静音/爆音。这是分段拼接最常见的缺陷，不属于"对齐"问题。

### 5.3 能力注册表与探针

能力记录粒度是 **接口 + 模型 + 音色 + 参数**，不是厂商。

字段：`供应商 / 接口 / 模型 / 音色 / 语言 / 时间戳粒度 / SSML / 支持的输出规格 / 验证日期 / 探针脚本 / 实际账号证据`。

SPEC 已定首版用**火山引擎豆包语音**、优先验证**单向流式 HTTP 接口**、固定一个清晰自然的普通话女声，试听锁定后记录音色与参数。本节的注册表与探针用于验证它是否成立，并为其后的替换留出余地。

**能力以探针实测为准，不以文档为准**。文档会变，探针结果不会骗人。探针套件对自家账号跑一遍，结果写入注册表。

已知现状（**均待用实际账号复验**）：

| 服务 | 时间戳粒度 | 备注 |
|---|---|---|
| 火山引擎 | 官方接口已说明支持开启字级字幕 | 不必再写成"仅第三方实践"，但须实测 |
| MiniMax | 长文本异步接口支持**句级** | 不可推广到其全部接口 |
| 阿里云 ISI | 字级（`enable_subtitle=true`） | 短文本 REST **不返回**；仅部分发音人支持；需 WebSocket/SDK |
| 讯飞 | 文档未承诺字级 | 单次 <8000 字节；QPS/并发流控严格 |

**不锁死音频规格**：火山该接口的 OGG Opus 仅支持 48k，其他格式规格各异；文件大小取决于码率。此前"65 秒约 260 KB"只能作为特定编码配置下的估算，不作为设计约束。

### 5.4 缓存与成本

缓存键：`合成单位（句/段）+ 供应商 + 模型 + 音色版本 + 语言 + 语速 + 发音规则 + 输出规格 + 实际合成文本哈希`。段级文本哈希覆盖整段及影响合成的句间分隔；改变句子切分还需重新计算句子映射与字幕。

按合成单元缓存有价值，但**不是唯一省钱手段**。同等重要的是：减少无效重试、缩小修改范围（§3.3）、避免因局部标点改动触发全篇重合成。复用前须校验当前企业与成员的访问范围，不能仅凭内容哈希访问其他成员的私有音频。

TTS 必须走**服务端凭证代理**：阿里 token 会过期需刷新；讯飞需 hmac-sha256 签名且时钟偏移 >300 秒即拒。密钥不得进入产物、日志或前端（`AGENTS.md`）。

### 5.5 兜底

拿不到时间戳时，**强制对齐是候选兜底方案，不是承诺**。WhisperX 等项目自身列有数字、特殊字符等无法正确对齐的限制，不能对外承诺普遍准确。是否启用取决于实测覆盖率。

## 6. 原型库

### 6.1 分层

```
内容原型（讲什么）× 版式骨架（怎么分屏）× 动画基元（怎么动）  → 主题 token 上色
```

**原型不是模板文件，是渲染器里的纯函数 + 一份容量契约。**

新增一层（相对旧引擎）：

```
学科原语层：坐标系与曲线采样 / 矢量与合成 / 容器与浸没 / 电路拓扑
```

技术类原型只需**排版**；学科类原型需要**计算几何**，必须由程序算出图形，不能靠模型给坐标。这是新引擎最大的新增工作量。

旧引擎已有可用基础：`fixtures/animation-scenes-v1.json` 已覆盖几何、受力、函数、光学、刚体运动、实验仪表，图元含 `line / circle / polygon / arrow / plot / right_angle / partition`。学科原语应在此基础上扩展，不另起一套。

### 6.2 原型目录

首版围绕**已有课题**选择，不以通用技术讲解原型起步。

**学科原型（首版重点）**

| 原型 | 对应课题 | 依赖的学科原语 |
|---|---|---|
| `derive.steps` | 公式推导、条件比较 | 无（版式分步即可，可先用于内部打通流程；不能仅凭文字逐条出现完成用户验收） |
| `func.params` | 一次、二次函数 | 坐标系、表达式求值、曲线采样、参数变化 |
| `geo.transform` | 平移、旋转、面积关系 | 坐标系、多边形构造、变换矩阵、面积计算 |
| `body.forces` | 浮力、浸入、平衡 | 容器/流体、矢量箭头、合成与标注 |
| `circuit.path` | 串并联、开关、电流路径 | 电路拓扑（**建议先做固定拓扑 + 状态枚举，不做通用求解**，成本最高，后置） |

**辅助版式原型（保留）**：`title.card`、`list.points`、`compare.columns`、`image.annotate`。

### 6.3 容量契约

每个原型声明能力上限，模型生成前**先校验**，超限即在方案阶段要求拆幕（而不是渲染完发现重叠）。

```json
{
  "id": "func.params",
  "version": 1,
  "capacity": {
    "curves": [1, 2],
    "params": [1, 3],
    "annotationChars": 12,
    "axisRangeLocked": true
  },
  "minDurationMs": 8000,
  "msPerObject": 2000,
  "motions": ["draw", "morph", "travel", "highlight", "count"],
  "fillExample": {}
}
```

原型**固定能力与约束，但不固定构图**：允许内容决定布局，避免"所有内容套同一种模板"。

### 6.4 工程要求

1. `render(data, theme, beat) → SceneNode[]` 是**纯函数**，同输入同输出。
2. 每个原型自带**塞满容量上限的最坏样例**，纳入回归。
3. 作者数据**锁原型版本**（`func.params@1`），否则改原型会让旧作品全部变样。
4. 组合限制：**一幕 = 1 个主原型 + 最多 1 个侧栏原型**。
5. 方案卡显示每幕的**中文教学表达说明与填充预览**，例如「参数变化演示」「受力对比」，让教师通过对话纠正选型。不要求教师理解 `func.params@1` 等原型标识；技术标识和版本保留在内部数据中。

## 7. 渲染与确定性

**渲染器不执行模型代码**（沿用旧引擎铁律）。模型只产出作者数据。

确定性承诺收窄为：

> 相同的**已解析作者数据** + 固定**素材、主题、字体、渲染器版本** → 产生**一致的 DOM/SVG 输出**。

不承诺跨浏览器像素一致；该项另行验收（§8.5）。

字体必须随包分发或内嵌，不依赖 CDN——否则"离线 HTML 包"的承诺不成立。

### 7.1 离线交付与播放验收标准（首版）

首版交付物明确为：**下载后直接双击打开的单个 HTML 文件**——不是文件夹，不是需要本地服务器或额外安装的工程。

| 验收项 | 标准 |
|---|---|
| 目标环境 | 先验收 Windows 上的 Edge 与 Chrome；其他浏览器与操作系统不在首版承诺内 |
| 断网播放 | 断开网络后仍能：播放声音、正确显示公式、暂停、跳转、教师分步播放 |
| 外链 | 包内不请求任何外网资源，CSP 禁止网络请求；字体与公式渲染资源内嵌 |
| 字幕对齐 | 字幕与实际语音偏差目标 **≤ 200 毫秒**（待实测确认，属目标值而非已达标结论） |
| 下载鉴权 | 平台内下载沿用成员私有鉴权与归属校验 |
| 下载之后 | **不再承诺持续受平台权限控制** |

最后一条是产品事实，不是技术缺陷：文件一旦落到教师本机，平台无法回收或撤权。须在下载入口明确说明，避免教师误以为删除作品即可收回已下载文件。

`≤ 200 毫秒` 是**暂定的工程目标**，不是已证实的感知阈值——本文档不主张任何毫秒数"低于人眼可察觉界限"。它当前的作用只是给实现与实测一个统一口径。

实测时须明确所测的量：**每句字幕的显示起止时间与该句对应语音边界之间的偏差**（不是整片平均值，也不是字幕文件与实际音频的全局偏移）。实测后如无法稳定达到，应如实下调承诺或改进口播切分，不得只改文档数字。

## 8. 校验与门禁

### 8.1 通用门禁

2026-10-20跨学科修复候选（未部署，实测见`animation-subjects-20261020.md`）：含内部动画的科学对象必须由外层句子锚点`tween progress`驱动，不能用`show/emphasize`代替。明确要求对象运动时，静态插图、文字淡入不算运动；“移动或高亮”保留教师给出的可选表达。依次高亮须覆盖需求中的每个结构并分开呈现；双向路线须有反向非文字动作。`follow_path`从对象当前位置出发，返向使用反序路径，拒绝瞬移。`text.attach_to`只继承目标平移和显隐；文字最后绘制，避免高亮底色遮字。上述为有限结构校验，不替代画面与知识人工审核。

- schema 校验（作者数据 / 构建结果字段分离）
- 元素重叠、出画、最小字号、对比度
- 多视口不溢出（1440×900、1920×1080）
- 单幕最短停留；阅读速度上限
- 字幕与语音对齐误差阈值（测量口径与目标值见 §7.1）
- **暂停、跳转、回放后画面、字幕和音频位置仍正确**（按 §4.1 / §4.4 验证，覆盖有声、固定无声停顿、点击等待及跨幕恢复）
- 字幕文本与实际旁白内容一致

### 8.2 学科正确性门禁

分两档，**不承诺全自动**：

**可自动判定**（必须实现）

- 函数：声明点是否落在曲线上（代入求值）、参数与曲线一致
- 斜率（首个验收课题的核心，须单独实现，**不能只比对"k 是否增大"**）：
  - k 的**符号**决定增减方向（k>0 上升、k<0 下降，须与坐标比例一并判定）
  - **|k|** 决定倾斜程度。比较两条直线的陡缓**只看 |k|，不要求 k 同号**——同一坐标比例下 k=−3 比 k=1 更陡
  - 旁白说"变陡"时，须满足 **|k| 确实增大**；仅"k 增大"不成立——**k 从 −3 增到 −1 是 k 增大，但 |k| 减小，直线变平**
  - 比较须在**同一坐标比例**下进行，否则"陡"的视觉判断本身不成立
  - **连续参数动画**另按一条规则处理：k 连续变化并经过 k=0 时已不是一次函数（k≠0），须在旁白中明确说明退化，或把区间拆开分段演示，不得静默穿过
  - 首个验收样例（一次函数中改变 k）可**限定在 k 同号的区间内**演示作为教学简化；这是**样例的取值约定，不是通用数学规则**，不得写入门禁的普适判据
- 受力：声明平衡时矢量是否闭合、对象/方向/标注与讲解一致
- 电路：串并联是否连通、开关状态与描述一致
- 几何：沿用旧引擎的直角/等长/等面积/拼图覆盖约束

**需抽样人审**（不自动通过）

- 物理情境合理性、符号与单位、教学顺序

### 8.3 重叠与遮盖

重叠检查**允许明确设计的遮盖、交叉与包含关系**，但许可范围由渲染器和原型契约限定。作者数据中的 `layers` / `allowOverlap` 仅表达意图，模型不能通过填写该字段自行豁免门禁。

程序只对契约允许的具体对象关系接受重叠意图，例如容器包含物体、几何拼合或曲线交叉；未声明或不符合契约的重叠仍报错。正文、字幕、公式与关键标签的可读性检查始终有效，不能因声明允许重叠就跳过。

### 8.4 视觉回归与截图回灌预算

- 沿用旧引擎抽帧思路（每幕 10%/50%/90%），关键帧不进入公共产物，按成员私有保存。
- 截图回灌模型**只针对变更幕与关键状态**，并设明确上限。
- **不采用"每幕多轮模型审核"**——避免形成"超时后整段恢复"的速度瓶颈。这与 `PLAN.md` 中对全项目最高技术风险点的判断一致。

### 8.5 跨环境验证

跨浏览器截图一致性单独验收，可设容忍阈值，不与 §7 的确定性承诺混为一谈。

## 10. 分期与验收

| 阶段 | 可验收成果 |
|---|---|
| **内部技术验证** | 作者/构建分离的数据模型、结构化补丁与依赖重算、**一个**学科原型、可定位时间的确定性渲染。**并行启动 TTS 能力探针** |
| **第一版端到端** | 首页对话 → 方案修改确认 → 一个知识点动画 → 一家 TTS → 句级字幕 → 离线 HTML。**用户验收必须包含真实动画 + 语音 + 字幕**；同时完成权限隔离、失败保存、取消释放及一次结算等基础保护（§10.4） |
| **第二版** | 补充学科原型、MP4 与字幕导出、扩大故障恢复场景及跨环境验证；基础保护不延后 |
| **后续** | PPTX / LMS、更多声音、多语言、克隆与多角色 |

### 10.1 关于"内部里程碑"

静态无语音 HTML 可作为内部里程碑，但**不作为用户验收内容**——否则与产品体验约定不符。

`derive.steps` 可先用于内部验证数据、补丁和渲染流程；首个用户验收样例建议采用 `func.params` 的窄范围任务：**改变一次函数的 k，观察直线倾斜方向和程度，保持 b 与坐标比例不变**。样例须包含实际曲线变化、同步旁白与字幕、观察停顿、暂停/跳转/回放和一次对话式局部修改；修改后检查相关内容与未受影响部分。所选 k 保持一次函数定义要求，涉及 k=0 的对比须明确此时已不是一次函数。

该样例验证一个知识点的端到端能力，不表示所有学科原型均已完成。

### 10.2 排期风险

第一版用户验收卡在语音上，而语音的未知量最大（尤其火山字级字幕须用真实账号与音色实测）。**能力探针不能等到第一版再做**，必须与学科原型并行。否则学科原型做完才发现要换厂商。

### 10.3 降级与结算

新引擎**不保留旧引擎的 L2 简化**，与 `docs/animation-rebuild.md` 一致：校验不合格时**同幕有界修复**（L1），仍失败即**如实失败**（L3），保留已完成内容并对教师可见。理由：自动简化会让成品偏离已确认方案和代表幕，且简化版能否算交付、能否结算都没有确定答案。需要更简单的表达时，由教师在方案阶段通过对话修改。不以样例冒充真实结果；修复尝试不重复计费。

重新测算的是**供应商成本**（文本生成、TTS、必要审核等），与教师的**业务积分价格**分别记录。新增 TTS 不自动意味着修改当前 40 积分单价；如需调整业务价格，须另行决定并更新对应产品约定，不能在实现中自行改价或补扣历史作品。

### 10.4 第一版必须完成的权限、任务与账务边界

- 复用现有认证与隔离机制：任务、方案、对话补丁、预览、音频、字幕、版本、事件流和下载均须校验当前企业与成员；私有素材和缓存不得因 ID 或哈希可猜测而被越权访问。
- 失败或超时保存已完成的作者版本、音频及有效构建结果，明确未完成环节并允许受控重试；不重复制作无关片段，不把缺语音或字幕的草稿标为完整交付。
- 取消停止后续工作并释放尚未结算的预留；迟到的模型/TTS结果不得覆盖新版本或把取消任务改成成功。供应商已发生费用与业务积分释放分别说明。
- 教师验收前只预留，完整产物经教师确认后结算一次；重试、补丁并发及重复确认不能重复预留或结算，失败保留原成果与正确账务。
- 基础边界沿用项目已确认的 HTTP 认证/隔离/额度/任务状态验收；渲染边界验证真实离线 HTML、音频和字幕输出及播放行为。跨环境扩大验证可放第二版，上述基础保护第一版即验收。

### 10.5 免费局部修改规则

SPEC 定「交付后每幕一次免费局部 AI 修改，首期不开放更多付费修改」。补齐边界：

| 情形 | 是否消耗免费次数 |
|---|---|
| 一次修改包含同幕的多个要求 | 算**一次** |
| 新修订构建成功**且教师接受** | 消耗 |
| 构建失败、教师取消、系统纠错重渲染 | **不消耗** |
| 拆幕、合并幕 | 首期**不支持**作为免费局部修改；按新生成请求处理并提前提示 |
| 更换知识点、新增教学目标、整体重做 | 不是修改，按新生成请求计费并提前提示 |

- 次数按**幕**记账，键为 `sceneId` 而非显示序号，避免重排后串号或变相刷新额度。
- **首期免费局部修改不支持拆幕、合并幕。** 理由：拆并会产生新的 `sceneId`，无法可靠继承原幕的剩余次数；与其先设计继承规则，不如先不支持——需要拆并时按新生成请求处理。
- **每幕同一时刻只允许一个待接受的修改。** 接受新修订与消耗免费次数必须**在同一事务内同时成功**：不允许并发接受两份修改，也不允许出现"次数已扣但接受失败"或"已接受但未计次"的中间状态。
- 修改期间**旧成品仍可正常播放与下载**，不因新修订在构建而不可用。
- 已结算作品的修改若最终失败，**不释放原消费**——原交付已经成立，与"未交付的失败"是两回事。
- 修改后的确认同样绑定内容（§3.4）；未被接受的新修订不覆盖已交付版本。

### 10.6 失败恢复与调用上限

§10.4 写了"失败释放预留"与"允许受控重试"，二者之间的衔接在此补全：

- 恢复**只补未完成内容**：已完成并保留的幕（含已确认的代表幕）不重做。
- 恢复时**重新检查权限与余额并重新预留**，不得沿用已释放的预留。
- **已释放的预留保持原账务记录，不做合并、不回写、不抹平**；只结算**当前有效的那一笔**预留，整个生成请求最多结算一次。历史预留与释放记录照原样保留，供账务追溯。
- **重启、自动重试与同请求恢复不清零调用计数**。计数随生成请求持久化，不能靠反复恢复绕过下面的上限。
- 恢复有时间窗与次数上限；超限按新生成请求处理并提前提示。

**调用上限必须分类设定**。"有界重试"不是可执行约束，且各类调用若共用一个计数会互相挤占、让定位失真：

| 用途 | 计数口径 |
|---|---|
| 免费方案讨论 | 对话不预留积分，但模型调用有供应商成本，须设单次生成请求的对话轮次上限 |
| 方案 JSON 修复 | 同幕有界修复，计入该生成请求 |
| 分镜 / 画面修复 | 与上分开计数，避免互相挤占 |
| TTS 调用 | 按幕计，首次合成与重试分别计数 |
| 截图视觉审核 | 只针对变更幕与关键状态，设单次生成请求的截图张数上限 |

各上限的具体数值须以真实联调成本核准后写入配置，本文档不臆造数字；当前均为**未定**（§11）。

## 11. 风险与未决

| 项 | 说明 |
|---|---|
| 学科原语工作量 | `body.forces`、`circuit.path` 的成本尚未测算，可能显著超出预期 |
| 电路拓扑 | 通用求解风险高，已决定先固定拓扑 + 状态枚举 |
| 强制对齐 | WhisperX 等存在数字/特殊字符对齐限制，只能作候选兜底 |
| 时长预算 | 2026-10-20候选按逐句真实语音实测保守估计：非ASCII非空白字符约0.3秒、ASCII词约0.45秒、每句0.3秒起始量，另加实际时间轴句间间隔和显式教学停顿。无现存音频时超出请求上限则在方案阶段要求精简；已有音频的时长修订以实测为准，不被估算阻塞。只规划上限，不把字数当成片验收，不自动加速或补空白。60–90秒规划取中间值并留余量，英语需单独安排观察、跟读和思考。成片仍以真实解码音频和固定停顿核算；未达下限同样不得交付 |
| 制作耗时 | SPEC 目标 2–5 分钟（不含排队），与成片时长分开报告；学科原语完成后须实测 |
| 成本与积分单价 | 含 TTS 后重新测算供应商成本；当前 40 积分业务单价不自动变更，改价另行决定 |
| 调用上限数值 | §10.6 各类上限均未定，须以真实联调成本核准 |
| 字幕对齐 | §7.1 的 ≤200 毫秒为**目标值，尚未实测**；火山单向流式接口的句级时间戳返回形式待真实账号验证 |
| 离线文件不可回收 | 下载后不再受平台权限控制，属产品事实，须在下载入口明示（§7.1） |
| 旧作品 | 已交付动画不重做、不补扣积分（沿用 `animation-quality-v1.md` 约定） |
