各科实际需要的图由验收前的教学任务决定。没有图也能讲清的页面不为了覆盖率强行插图；要求史料的任务不能拿无标识的示意图替代。

### 一课的闭环

需求→规划及目标映射→代表页预览→逐页检查→扩展全课→手动修改一页→受影响检查失效与重检→全课核验→明确确认→结算一次→PPTX下载→桌面打开及截图。另验证一次缺证或错误场景确实阻止交付，不通过关闭审核或自动同意问题绕过门禁。

显式检查：

- 每个核心目标有讲解和具体学生考查，所有页关联有效目标，前置依赖顺序合法；人工判断考查任务是否真正测到该目标。
- 最终全课核验绑定当前内容版本，无error/missing_evidence阻塞；记录审核配置，disabled/sample不算真实事实核验通过。
- 已采用图片的相关性、图注身份/年代/地点与证据分别核对，来源缺失或错误不得按图片已下载判通过。许可未知如实记录，相关性不等于事实或许可证明。
- 预览页不被无故覆盖，保存和下载内容一致，目标和图片不在导出时消失，额度只结算一次。
- 发现失败保留输入及产物，先复现，再按AGENTS约定的HTTP或真实渲染边界写失败用例并修复；不能只挑选成功课件。

首批全通过后，再对各科独立重复两次，报告每科成功数/总数、人工修改和重试数；3次仍是小样本，不宣称已证明普遍稳定。未运行的学科列为未覆盖。

## 3. 长对话联合验收

用真实Vue页面与真实需求模型连续沟通至少10轮，并继续到实际摘要触发，短消息通常需13轮或更多。前期不发送制作指令，断言没有创建任务或预留制作积分；对话模型本身的供应商调用不称为零成本。

建议脚本顺序：

1. 提出课题、学生基础、时长、重点、配图、练习、答案备注等要求，保留两项后面会修改的旧要求。
2. 观察真实摘要事件及前后状态，核对早期关键要求仍在有效需求中；不手工设置compact_context绕过界面触发。
3. 在界面手动将45分钟改为40分钟，修改一项学习目标和需求摘要；再聊一轮，确认最新值覆盖旧值。
4. 刷新并恢复该历史，核对有效需求及作品入口；直到明确开始制作前不出现制作任务。
5. 明确点击/发送开始制作，核对实际POST /api/tasks输入与当前需求一致，且只创建一个任务、只预留一次。
6. 继续到真实预览、完整课件、当前内容全课核验及下载；记录摘要、手工改动、最终任务输入的差异。

主成功流程之外，另用已约定HTTP及浏览器边界验摘要失败、停止/迟到回复、重复点击和成员切换；不得为制造故障额外消耗不必要的真实模型调用。真实主流程与fixture故障验收分别标记。

## 4. PowerPoint放映与课堂

建立同课对照包：静态、GIF、原生点击。GIF覆盖函数参数和通用科学动画；点击覆盖曲线、标记和图例的首次隐藏、每击一步及前后翻页。网页预览或导出静态截图不能替代放映。

本机可自动化部分：桌面PowerPoint实际放映，录屏或在不同时间截取动画区域；确认GIF帧在变化、标签可读且不是翻页/光标变化，确认点击前后对象数量和顺序；关闭重开文件再次检查。保存PowerPoint版本、系统、字体列表、时间戳和录屏，不只读OOXML/COM效果表。

人工部分：至少在另一台目标课堂电脑用实际放映软件检查，记录缺字体/替换、公式、换行、裁切、图片、GIF、点击和备注；教师按真实讲解节奏评价能否停在关键状态、揭示答案和回看。其他电脑、其他软件及真实课堂尚未测时保持pending，不能由本机脚本代签。

发现兼容问题提供明确静态对照或既有网页演示路径，由教师选择；不要静默把GIF替换成首帧并称为动态验收通过。不默认新增字体分发、视频转码或运行中课堂系统。

## 5. 教材解析与教学视觉质量

先建小型人工校对材料集：上下标/分式/根式/矩阵、双栏文本、跨页表格、扫描页、PPT组合图、历史照片图注和生物结构图。每份保存实际原文件、页码、人工核对文本及关键数值/符号。现有提图只支持内嵌位图，扫描图不等于已OCR，矢量图不等于已自动提取。

逐页对照原文和提取结果，把警告变为可定位的页号及问题记录。涉及关键公式、单位、事实或题目条件的丢失必须补正/提供原页图依据后重跑；无法读出时保留未核验并给出换文件/补文字的操作，不能让模型补猜。优先修已出现的具体问题；是否增加OCR/公式识别由材料集暴露的缺口另定。

教学质量使用同需求、同资料、同内容范围的旧/新版本对照，匿名顺序交给学科教师评分；至少保留事实、目标与练习一致性、表达/可读性、配图/图注、节奏五项及修改理由。建议0–4分，每项≥3且无关键事实/公式/答案错误；这是拟采用门槛，不是已经取得的分数。记录评阅人数、分歧与裁定；一个总均分不能掩盖事实错误。模型自评和图片数量不能代替教师评价。
