# 课件提交被旧健康状态拦截

2026-10-16 截图中的“课件服务尚未更新”由前端提交保护产生。排查时实际 8080 后端和 8000 排版服务都返回 `courseware_media_version=media-v1`，首页资源与当前发布构建一致。前端仅在首次挂载读取健康状态，首次读取失败或保留旧版本状态后，点击原结果卡片重试也不会重新读取，创建请求在发往后端前即被拦截。

用 `node scripts/browser-service-readiness.cjs` 注入第一次旧健康状态、后续正常状态，可稳定复现相同中文错误和任务创建次数为零。修复在共用 API 提交保护中重新获取健康状态，仍不兼容则阻止创建；短暂不可达提示原地重试，不再要求刷新丢失首页对话。独立课件页和首页嵌入课件共用此检查。健康检查是 GET，不自动重发创建请求，原执行的幂等键不变。真正的渲染能力检查仍由后端执行。

验证：

- `TEST_READINESS_CASE=recovered`：旧状态恢复后自动检查，创建一次任务，对话保留。
- `TEST_READINESS_CASE=outdated`：二次检查仍旧时不创建任务，服务恢复后点击重试成功，创建一次任务。
- `TEST_READINESS_CASE=offline`：二次检查 HTTP 503 时不创建任务，恢复后原地重试成功，创建一次任务。
- `node scripts/browser-conversation.cjs`：现有八组首页流式回复、结构化编辑、工具路由、幂等、切换和响应式检查通过。
- Vite 生产构建通过。浏览器测试使用显式 fixture，不代表付费模型或真实用户的新生成任务已经执行。

发布仅更新已部署目录的前端 hash 资源和 index，保留旧资源供打开的页面使用，不替换 Go 二进制或排版源码。已打开页面需要刷新一次加载修复；新页面遇到服务恢复可直接点击结果卡片的重试。
